# 阶段性结束判据（v3.19 时点）

用一句话说结论：**代码侧的迭代可以停在现在；结论要能对外讲，还差两步。**

## 一、三个闸门

| 闸门 | 判据 | 现状 | 剩余成本 |
| --- | --- | --- | --- |
| **G1 可交付** | CI 绿、单测全过、文档与复现脚本齐全、任一改动可用 500 题指纹验证零漂移 | **已满足**（94 例单测、CI 通过、regress/replay/pair_report/splits/audit 全在仓库） | 0 |
| **G2 结论可信** | ① 提示词不再含评测集原句；② 在 **test 切分（249 题）** 上跑一次并冻结对外数字（注明日期、模型快照、单轮） | 未满足：L1–L3 仍是抽取提示词里的题库实体；所有分数都是 in-sample | 重抽取 ≈3 h + test 跑数 ≈40 min |
| **G3 主张成立** | 同一 test 切分、同一 judge 下，与全上下文基线做**配对**比较，才允许说“追平/超过” | 未做（基线数字来自 Oracle 全量，不是 test） | 基线 test 一轮 ≈2 h + 配对分析 |

## 二、建议的停止点

- **课程项目 / 结项**：做到 **G2** 就停。此时对外表述是“在 held-out 的 249 题上 X%”，
  而不是“我们在 500 题上提升了 0.4pp”。
- **答辩要讲“结构性超越”**：必须补 **G3**，否则只能讲机制（时序/聚合/拒答三条确定性路径），
  不能讲分数对比。
- **不建议继续做的**：在 Oracle 全量上继续修个位数错题（in-sample、边际趋零、有过拟合风险）；
  S 档全量 500 题（117 h 机时，性价比低，除非明确要求）。

## 三、为什么现在可以停

1. **结构欠账清零**：`fusion.py` 1521 → 151 行；事件构造单点；开关随实例；`read()` 分层。
2. **可移植性闭环**：日期格式化不再依赖平台 `strftime`，CI 与本地输出一致。
3. **过拟合面收敛**：提示词示例 L4/L5 已抽象化，词表 L6 已分层，审计脚本可作门禁。
4. **失败有账**：本轮 4 个读侧候选（计数协议 / 时间窗 / 逐候选过滤 / 锚点算子）全部被证伪并回滚，
   说明廉价涨分空间已尽；继续改只能动写入或数据模型，那是下一个量级的投入。

## 四、若还要继续，只做这三件（按顺序）

1. **L1–L3 重抽取**（3 h）：清掉抽取提示词里的 `3 lunches` / `amateur comedians` / `Instant Pot` 等原句，
   与下一次全量重建合并执行，避免缓存半新半旧。
2. **test 切分报数**（40 min）：`run_eval --split test` + judge，冻结一个带日期的对外数字。
3. **基线 test 配对**（2 h，可选）：只在需要“超过基线”的表述时做。

## 五、冻结纪律

- 打 tag `v3.19-final`，此后 `results/golden-oracle500.json` 与 15 题夹具不再随代码改动重建；
- 任何新实验另开分支，用 `regress --check` 对比冻结基线；
- 对外材料只引用带日期与模型快照的数字，禁止把不同批次的总分直接相减。
