## 三、建议的停止点

- **课程项目 / 结项**：现在就可以停。对外表述是"held-out 249 题 88.65%，
  与全上下文基线统计打平；时序题 +7.2pp"。
- **答辩要讲"结构性优势"**：用 test 的分题型数字（TR +7.20、SS-P +3.33），
  不要用全体 +1.90 当主证据——那部分增量几乎都在 dev 上。
- **不建议继续做的**：在 Oracle 全量上继续修个位数错题（in-sample、边际趋零、
  有过拟合风险）；S 档全量 500 题（117 h 机时，性价比低，除非明确要求）。

## 四、为什么现在可以停

1. **方差已测干净**：4 轮 89.60–90.00（sd 0.23），test 88.35–89.16（sd 0.38）；
   稳定错题 42、摇摆题 21。1–2pp 的单轮差值已被证明不可作为结论。
2. **判分可复现**：同一批 hypothesis 重复判分两次，500/500 逐题一致；轮间差异
   全部来自答案采样，不是 judge 抖动。
3. **消融已刷新**：四组机制在当前代码上重跑，证据地板 −3.6pp 成为最大单机制，
   与 v3.6 时代的"−1、未达显著"不同——这条结论改变了下一步的优先级。
4. **结构欠账清零**：`fusion.py` 1521 → 151 行；事件构造单点；开关随实例；
   `read()` 分层；对外 facade 与独立接口文档齐备。
5. **失败有账**：4 个读侧候选（计数协议 / 时间窗 / 逐候选过滤 / 锚点算子）
   全部被证伪并回滚，说明廉价涨分空间已尽。

## 五、若还要继续，只剩一件事

**S 档全量 500 题**（≈117 h 机时 + judge 费用）。它不改变方法结论，只提升
可比性；没有硬性要求时不做。若做，正确表述仍是"Oracle 上打平、时序领先"，
不能把 S 档数字与 Oracle 直接相减。

## 六、冻结纪律

- 冻结 `results/golden-oracle500.json` 与 15 题夹具，不再随代码改动重建；
- 判分明细含数据集原文，留在本地 `results/`，仓库只提交 `docs/evidence/` 的聚合结果；
- 任何新实验另开分支，用 `regress --check` 对比冻结基线；
- 对外材料只引用带日期与模型快照的数字，禁止把不同批次的总分直接相减。
