3. v3.5 方案（三改，全部确定性/读取侧优先）

改动 A：KU 窗口计数修正（agg 管线的窗口强制）

问题：0ddfec37 的 "first three months" 是从首次收集开始的相对窗口，不是从 question_date 倒推。解析层把它当无窗口 → 全部 20 被返回。

方案：解析层新增 window_anchor="first_event" 信号——当问题含 "in the first N months/weeks of collecting/doing X" 时，窗口起点 = 该实体首个事件的日期。执行器：取该实体最早事件的 valid_from 作为窗口锚。

改动 B：SS-A 逐字引用库（assistant 枚举保真）

问题：4 道 SS-A 全是 assistant 枚举长列表里的第 N 项细节。句子级摘录截断 260 字符 + BM25 相关性排序对"第 N 项"定位失败。

方案：写入期为 assistant 枚举块（编号列表 1. 2. 3.）建立序号索引：ordinal_map[session][(list_no, item_no)] = item_text。查询期 PREMISE/ORDINAL LOOKUP 已有第 N 项定位，扩展支持 "which X did I say / the move after N" 类：assistant 语句逐句存入 quote 库，lookup 意图优先搜 quote 库（逐字保留，不做摘要）。

改动 C：supersession 确定性后检（写入期，非 LLM）

问题：07741c45 类"位置更新"在重采样下不稳定；e66b632c 的抽取幻觉需要兜底。

方案：写入期确定性后检——新事件与既有事件满足（同 subject + 同 category + 词面 Jaccard ≥ 0.45 + stated_at 更晚）且 LLM 判了 new/supplement 时，升级为 evolve（旧值封口）。阈值从 0.45 起步离线扫参。这与 v3.2 的 LLM dedup 不同：完全确定性，可用缓存离线验证，不引入采样方差。
