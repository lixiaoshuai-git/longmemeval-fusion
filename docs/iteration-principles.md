# 迭代原则（含防过拟合条款）

本文件是 fusion 记忆系统工程迭代的硬约束。每轮改动前对照检查，改动后在
`docs/iteration-log.md` 里注明遵守/违反了哪几条。原则编号固定，便于引用。

---

## P1 先归因，再改代码

任何改动必须先有失败证据：错误题的上下文、候选集、算子输出或调用日志。
禁止"觉得应该有用"就加机制。历史上 v3.10a/b/c、v3.7 近逐字扩展都是
无证据加机制，全部回滚。

## P2 一次只改一个变量，并留回滚点

单轮只动一个机制；改动前后各存一份可比的产物（缓存 tag / golden）。
出现可复现回退立即回滚，不叠加第二个变量去"救"第一个。

## P3 判定用配对，不用总分

同一批题上的 fix/break 才算证据。单轮总分受重采样影响（实测：未改动的
416 题自己就能漂 7 题 ≈1.4pp）。报分必须同时给出：

- 改动组：n、基线→候选、fix/break；
- 未改动组：净变化（作为噪声基线）；
- 若未改动组波动大于改动组收益 → 只能报"因果增益"，不能报总分提升。

## P4 零调用优先

能用缓存回放回答的问题，不调用模型；能用确定性规则判定的，不写提示词。
`regress.py --check`（500 题/8 秒）、`replay_trace.py`、`--audit-plans`
是第一手段。

## P5 提示词只写规则，不写题库

**禁止**把评测集里的实体、数字、原句写进提示词当例子。需要举例时用：

- 抽象占位：`<a count>`、`<a named object>`、`<a price>`；
- 或与评测集无关的合成内容（如 "a 12-kg bag of rice"）。

理由：示例会锚定抽取与作答，等于把测试题写进模型输入，属于数据泄漏。
此类泄漏不改变"机制是否正确"，但会让分数虚高且不可外推。

## P6 词表分层

- **语言通用层**（代词、疑问词、量词、时间词）可以硬编码；
- **领域词层**（tank / gallon / apartment / undergrad / course …）默认空，
  按数据集注入；核心规则不得依赖领域词，否则换语料静默失效。

判断标准：把这条词删掉，换一个数据集是否还能工作？不能，就是领域词。

## P7 修复要带"同机制不同措辞"的用例

每条行为修复至少配 3 条合成用例，覆盖同一机制的不同表面形式
（如 catch/caught、buy/bought、hide/hid）。只覆盖原题的用例不算通过。

## P8 保留 dev/test 切分

500 题按 `md5(question_id)` 固定切 250/250：**dev 用于找问题与调参，
test 只在需要对外报数时跑一次**。历史结论（v3.10 之前）全部是在全集上
选择并验证的，标注为 *in-sample*，不得当作外推证据。

## P9 记录失败与回滚

否决的候选也要写进 iteration-log：机制、影响面、否决依据。否则下一轮
会重复试同一条路（v3.10a 计数协议、类别硬过滤都差点被重试）。

**L5 的验证结果（值得单独记一笔）**：把两个题库例子换成"类别词 vs 成员 / 产品 vs 属性"
的抽象说法后，24 题上仍是 **16 → 23，7 修 0 坏，修好的题号完全相同**。说明
上一轮的收益来自"不要把词汇不匹配当成信息缺失"这条规则，而不是例子本身——
这是本轮唯一一次可以声称"机制而非措辞"的证据。

**结论**：泄漏存在但影响面有界（题面命中并集 12/500 = 2.4%）；最严重的是
抽取提示词里的数字与实体示例（L1/L2），它们可能在写入期就锚定了"要保留
哪个数"。修复顺序：L5（本轮，零成本）→ L4（10 min 重解析）→ L1–L3
（需 3h 重抽取，与下一次全量重建合并）→ L6（词表分层）。

**方法论层面的既有问题**：v3.10–v3.12 三次"保留"的改动，全部是
"在同一 500 题上找错 → 在同一 500 题上验证"，属于 in-sample。缓解手段
（已做）：配对比较、未改动组噪声对照、两到三轮重复采样、检查"修好的题
里有多少事前没看过"（v3.12 为 4/7）。这些不等于 held-out，故结论只能
表述为"机制修复"，不能表述为"泛化能力提升"。
