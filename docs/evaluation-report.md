## 5. 成本 / 延迟 / 效率（实测）

| 项 | 数值 |
|---|---|
| 写入侧（冷缓存全流程） | ≈8.0M prompt tokens / 500 题（≈16k tok/题，含逐轮抽取+关系分类）；4 并发 53.5 min |
| 答题侧（检索上下文 + 作答，10 题采样） | **2,331 prompt + 44 completion ≈ 2,375 tok/题** → 全量 ≈1.2M tok |
| judge 侧 | 111k prompt tokens / 500 题（≈222 tok/题） |
| **检索延迟（记忆系统本体，60 题采样）** | **read mean 6.3 ms / p50 6.6 ms / p95 11.3 ms / max 12.4 ms** |
| ingest 本地处理（缓存命中） | 3 ms/题 |
| 记忆库规模 | ≈33 events + 20 evidence turns / 题 |
| LLM 调用次数 | 写入期 ≈25 次/会话（可缓存复用）；答题期 1 次/题 |

Oracle 档 haystack 本身很小，答题侧成本与全上下文相当——**记忆系统的 token 优势在 S/M 档兑现**（S 档 haystack 115k tok vs 我们 ≈2.3k tok/题）。

## 6. 方差披露与失败模式

**运行间方差（temperature=0 仍非确定）**：基线双运行翻转 37/500 题（±1.4pp）；SS-P 同上下文两版摆动 ±6.7pp（judge/reader 噪声重灾区）；因此本报告所有结论均基于多轮均值。

**judge 噪声**：对 66 道判错题的独立语义审计——42 道为误判（措辞/表述差异），真实语义准确率估算 ~91.6%；22 道真错的构成：_abs 越权硬答 ×4、±1 计数 ×5、排序错 ×4、槽位最新值 ×4、选择器错 ×4、差值 ×1。

**迭代史中的失败实验**（全部记录并回滚，见 docs/iteration-log.md）：v3.1 渲染分层锚定（-1.4pp）、v3.2 LLM 批内去重（-2.2pp）、v3.5 窗口锚/序数升级（无正证据）、v3.7.1 recency 引用（假设证伪）、P3 词面去重标定否决（复述对与同模板不同事件对在 Jaccard 上不可分）。

## 7. 边界与局限

1. Oracle 档架空了会话级检索（0 干扰会话）；S/M 档需在确定性执行器前插入混合召回（接口已预留，未评测）。
2. judge 为 glm-5.2 代跑，64% 误判率意味着本报告分数系统性低估语义水平；正式口径以项目组官方 judge 复跑为准。
3. 长枚举（>12 项）抽取覆盖不全，序数查找仅覆盖点查询。
4. 遗忘/生命周期模块已实现并经 CLI 验证，但 Oracle 档无记忆损失实验，其策略参数未经 S 档调优。
5. 消融矩阵为单轮运行，个别 Δ 在 ±1.4pp 采样方差内（已在表中注明），机制性结论以多轮历史数据交叉印证。
