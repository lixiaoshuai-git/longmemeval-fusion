# 评估报告：长期交互式 AI 记忆系统（fusion v3.21）

D.I.V.E. × 川大 · 交付物 4 · 2026-11-14
基准：LongMemEval Oracle 档 500 题 · 复现步骤见 README §运行方法

---

## 0. 一句话结论

在 held-out 的 **test 249 题**上，fusion 四轮均值 **88.65%**，全上下文基线
**88.45%**，配对差 **+0.20pp（95% CI −3.61…+4.12，McNemar p=0.50）**——
**统计打平**。可以主张的是**结构性优势**：时序题在这 249 题上高 **7.20pp**，
且这一优势在 dev、全体、以及历史多轮里方向一致。不能主张"总分超过基线"。

## 1. 评测配置

| 项 | 值 |
|---|---|
| 数据 | `longmemeval_oracle.json`，500 题，官方流水线（时间序 ingest → 回答 → hypothesis） |
| 切分 | 固定 dev 251 / test 249（`scripts/splits.py`，按题型分层 + md5 交替） |
| 答题模型 | glm-5.2（OpenAI 兼容端点，temperature=0，关思考） |
| 评判模型 | glm-5.2 代跑官方 `evaluate_qa.py` 提示词（**正式成绩以项目组官方 judge 复跑为准**） |
| 轮数 | fusion 4 轮、全上下文基线 4 轮、judge 重复 2 次；消融各 1 轮 |
| 方差口径 | 报 mean ± 样本标准差；单次差值 <3pp 不作为结论依据 |
| 证据 | 聚合结果见 `docs/evidence/`，原始判分明细留在本地 `results/`（含数据集原文，不入库） |

**关于 judge 的两个不同问题**（不要混为一谈）：

1. **可复现性**——同一批 hypothesis 重复判分两次，500/500 题标签完全一致。
   轮间 0.2–0.4pp 的差异**全部来自答案采样**，不是判分抖动。
2. **口径一致性**——judge 是 glm-5.2 代跑，和官方 GPT-4o 不是同一把尺子。
   历史语义复核提示这把尺子偏严；这是**系统性偏差**，重复判分无法消除，
   只能由官方复跑校准。

## 2. 主结果（4 轮）

| 系统 | 轮数 | 分数分布 | mean ± sd |
|---|---|---|---|
| 全上下文基线（附录 F.1 禁作交付，仅上界探针） | 4 | 87.00 / 88.40 / 88.80 / 87.40 | **87.90 ± 0.84** |
| **fusion v3.21（当前代码）** | 4 | 90.00 / 89.60 / 90.00 / 89.60 | **89.80 ± 0.23** |
| fusion v3.6（历史） | 3 | 87.00 / 85.60 / 87.80 | 86.80 ± 1.11 |
| fusion v3.4.5（历史） | 3 | 86.00 / 85.60 / 85.40 | 85.67 ± 0.31 |
| fusion v3.7（verbatim 扩展，已回滚） | 3 | 86.60 / 86.80 / 86.20 | 86.53 ± 0.31 |

分切分看，故事完全不同：

| 切分 | 题数 | 基线 | fusion | Δ | 配对 95% CI | McNemar p |
|---|---|---|---|---|---|---|
| 全体 | 500 | 87.90 | 89.80 | +1.90 | −1.00…+4.75 | 0.064 |
| dev（调参用过） | 251 | 87.35 | 90.94 | +3.59 | −0.70…+7.77 | 0.081 |
| **test（持有集）** | **249** | **88.45** | **88.65** | **+0.20** | **−3.61…+4.12** | **0.50** |

**读法**：全体 +1.9pp 的增量几乎全部落在 dev（+3.6pp）；到没参与过任何
调参的 test 上只剩 +0.2pp。这正是"在 dev 上改、在 test 上验"的意义——
**总分层面不能宣称超越上界探针**，只能宣称打平，并给出机制层面的结构性证据。

| single-session-user | 70 | 97.86 | 97.14 | −0.71 | 35 | 97.14 | 97.14 | 0.00 |

两条稳定结论、一条稳定欠账：

- **时序是结构性优势**：全体 +7.7、test +7.2，两套切分同向且幅度接近。
  机制上对应确定性的时间归一化、时间线渲染、`fact_at_time` 算子。
- **偏好题反超基线**：全体 +1.7、test +3.3。v3.8 的偏好分段前置是有效改动。
- **助手侧事实是最大欠账**：全体 −7.1、test −10.7。全上下文能逐字看到助手
  原话，我们把助手轮压成"专名 + 教学型事实"，细节在压缩中丢失。
  KU 在 test 上 −5.1 也属同一类代价（旧值/新值需要原句语境）。

## 4. 消融矩阵（当前代码，单轮，全量 500 题）

基线为 4 轮均值 89.80；轮间噪声带宽 0.4pp（89.60–90.00）。配对数是对
四轮基线逐轮相减后的均值（负=掉题）。

| 关闭的机制 | Overall | Δ | 配对净变化 | 靶题型信号 |
|---|---|---|---|---|
| 证据地板（句子级原文兜底） | 86.20 | **−3.60** | −18 | TR 89.66→81.95（−7.7）、MS 82.89→78.20（−4.7）、SS-P 89.17→83.33 |
| 句子级摘录 | 88.20 | **−1.60** | −8 | SS-A 92.86→89.29（−3.6）、TR 89.66→86.47（−3.2） |
| 宽口径前提校验（`PREMISE_PROPER_ONLY=0`） | 88.80 | −1.00 | −5 | KU 93.27→91.03、MS 82.89→81.20；`_abs` 持平 80.0 |
| 算术注记 | 89.20 | −0.60 | −3 | KU 93.27→91.03；其余在噪声内 |

与旧报告（v3.6 口径）相比，最大的变化是**证据地板从"−1、未达显著"变成
"−3.6、最大单机制"**。原因不是地板改了，而是 v3.20 的抽取提示词收紧后，
事实层的覆盖率下降，原文兜底从"冗余"变成了"主路径之一"。这条结论直接
影响下一步：**任何进一步压缩上下文的改动，都必须先补回召回，而不是继续省 token**。

历史对照（同属消融证据）：时间线渲染关闭时排序真错 4 题全错（v3.3 审计）；
PREMISE CHECK 在 v3.4 把 `_abs` 从 57% 拉到 80%。

## 5. 成本 / 延迟 / 效率（实测）

| 项 | 数值 |
|---|---|
| 写入侧（冷缓存全流程） | ≈8.9M prompt tokens / 500 题；6 并发 **3 h 58 min**（含抽取、关系分类、答题） |
| 答题侧（检索上下文 + 作答） | **2,348 prompt + 77 completion ≈ 2.4k tok/题** → 全量 ≈1.17M tok |
| judge 侧 | 111k prompt tokens / 500 题（≈222 tok/题） |
| **检索延迟（记忆系统本体，60 题采样）** | **read mean 6.3 ms / p50 6.6 ms / p95 11.3 ms / max 12.4 ms** |
| ingest 本地处理（缓存命中） | 3 ms/题 |
| 记忆库规模 | ≈33 events + 20 evidence turns / 题 |
| LLM 调用次数 | 写入期 ≈25 次/会话（可缓存复用）；答题期 1 次/题 |

Oracle 档 haystack 本身很小，答题侧成本与全上下文相当——**记忆系统的 token
优势在 S/M 档兑现**（S 档 haystack 115k tok/题 vs 我们 ≈2.4k tok/题）。
端点到期前实测：一次全量重答只需 **139 s（8 并发，缓存在）**，这让"多轮
方差"从每轮 4 小时降到每轮 2 分钟，是本轮能补齐 4 轮的直接原因。

## 6. 方差披露与失败模式

**轮间方差**：4 轮 89.60–90.00，sd 0.23；test 88.35–89.16，sd 0.38。
按题看：稳定对 437（87.4%）、稳定错 42（8.4%）、摇摆 21（4.2%）。
摇摆题对单轮总分的理论影响上限 ±2.1pp——**这解释了为什么 1–2pp 的单轮
差值不能当结论**，也解释了历史上"同批未改动题重采样漂 7 题"。

**答案文本 vs 判分标签**：相邻轮次只有 52–54% 的回答逐字相同，四轮全同
仅 41.6%；但判分标签的一致率是 97.2–98.4%。也就是说，模型**换了措辞、
没换结论**。对外报数应报标签层面的准确率，不应引用某一轮的具体措辞。

**judge 可复现性**：同一批 hypothesis 重复判分两次，两次都是 450/500，
逐题 500/500 一致。轮间差异既然不是判分抖动，就只能是答案采样——把两者
分开之后，"judge 噪声"这个含糊说法在本报告里被替换成"判分口径偏差"
（系统性、需官方校准）和"答案采样方差"（已被 4 轮均值吸收）。

**失败模式**（42 道稳定错题，按题型与 trace 归纳，非新调参依据）：
助手侧细节丢失（SS-A/KU 为主）、长枚举覆盖不全、多会话聚合的候选遗漏。
三者都指向同一处：**事实层压缩率过高时，原文兜底必须更宽**。

**迭代史中的失败实验**（全部记录并回滚，见 `docs/iteration-log.md`）：
v3.1 渲染分层锚定（−1.4pp）、v3.2 LLM 批内去重（−2.2pp）、v3.5 窗口锚/序数
升级（无正证据）、v3.7.1 recency 引用（假设证伪）、P3 词面去重标定否决。

## 7. 边界与局限

1. **只在 Oracle 档验证**。Oracle 架空了会话级检索（0 干扰会话）；S/M 档
   需在确定性执行器前插入混合召回（接口已预留，未评测）。
2. **judge 是代跑**。glm-5.2 与官方 GPT-4o 的口径差未知；本报告所有绝对值
   都应视为"同一把尺子下的相对比较"。
3. **test 只用于报数**。看到 test 结果后没有再改代码；后续若按 test 错题
   调参，该切分即失效，必须重新划分。
4. **消融是单轮**。−0.6pp 的算术注记落在噪声边缘，只能算"方向一致"，不能
   算"已证显著"；其余三项超出噪声带。
5. **压缩代价是结构性的**。SS-A −10.7（test）不是 bug，是"只留专名"的
   设计取舍；要补回来必须增加助手轮原文的保留比例，写入成本会上升。
6. **遗忘/生命周期**已实现并经 CLI 验证，但 Oracle 无记忆损失实验，参数
   未经 S 档调优。
7. **长枚举（>12 项）抽取覆盖不全**，序数查找只覆盖点查询。
