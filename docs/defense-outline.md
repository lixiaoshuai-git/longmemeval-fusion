## 4. 高概率 Q&A 预案

**Q1 为什么不用向量库/embedding？**
A：三个理由。①Oracle 档 BM25+确定性已打平上界，证据不支持引入的必要性；②架构文档预留了混合检索接口（S 档扩展路径），S 试点已定位 MS/TR 衰减正是词面检索的局限——这是下一阶段的第一个任务，不是遗漏；③P3 与动态窗口两次标定证明：在引入更重的检索层之前，必须先标定（我们两次零成本否决了无效方案）。

**Q2 分数可信吗？judge 是自己跑的。**
A：①judge 直接使用官方 `evaluate_qa.py` 提示词，不重写；②我们对 66 道判错题做了独立语义审计，**主动披露 judge 有 64% 误判率**——即我们的分数系统性低估语义水平；③多轮方差实验（同代码 ±1.4pp）与全部分数分布已公开；④正式口径以项目组官方 judge 复跑为准，JSONL 已就绪。

**Q3 有没有对测试集过拟合？（附录 F.1 第 4 条）**
A：无任何题目 ID 特判或硬编码（可 grep 验证）。迭代方式是"错题归因 → 修复**通用机制**"：PREMISE CHECK 对任意专名假前提生效、序数查找对任意编号清单生效、算术注记对任意聚合计数生效。反证：5 次失败实验全部回滚，包括两次看似合理但全量无正证据的改动——我们没有为分数保留机制。

**Q4 记忆系统和 RAG 有什么区别？**
A：RAG 是"检索原文给 reader"；我们在其上增加了三层：①**写入期结构化**（关系分类 new/merge/evolve/correct/supplement + 双时间轴几何），让"当前有效事实"可确定性查询；②**确定性执行器**——聚合/计数/时刻查询由代码完成，答出对话中从未出现的数字（coins 38）；③**守卫层**——拒答措辞协议与假前提拦截。消融显示每层有独立贡献。

**Q5 最自豪的一个点？**
A：temporal-reasoning **反超全上下文上界 +5.3pp 且跨 7 次采样稳定**。上界模型"看着所有原文"仍算错时间关系，而记忆系统用确定性时间归一化算对——这证明了课题的核心论点：记忆机制不是上下文的降级替代，而是能超越它的计算组织方式。

**Q6 SS-P 方差为什么那么大？**
A：实测同上下文摆动 ±6.7pp——这是 judge 对开放式偏好表述的判定方差，属品类属性（公开系统同病：协议间摆动 80pp）。任何针对 SS-P 的迭代必须以官方 judge 复跑为前提——这也是我们把官方复跑列为第一优先级的原因。

**Q7 AI 工具的使用边界？（附录 F.3）**
A：AI 辅助开发，但：①全部设计决策、实验、回滚有迭代日志与 commit 历史可追溯；②机制原理可在现场从代码讲起（关系分类 prompt、双时间轴几何、BM25 实现）；③评测纪律（多轮、方差、审计）是我们自己建立的。

## 5. 失败实验清单（诚实是最强的答辩武器）

| 实验 | 结果 | 学到什么 |
|---|---|---|
| v1 封闭谓词五元组 | 60%，数值丢失 | 自由文本事实 > 结构化字段 |
| v3.1 渲染分层计数 | -1.4pp 回滚 | 半权威锚点比诚实召回计数更糟 |
| v3.2 LLM 批内去重 | -2.2pp 回滚 | 过/漏合并并存；关系层是方差源 |
| v3.5 窗口锚+序数升级 | 无正证据回滚 | 冒烟分≠全量分 |
| v3.7/3.7.1 fact_current verbatim | 打平/更差回滚 | KU 假设证伪 |
| P3 Jaccard 去重 | 标定 NO-GO | 复述对与同模板不同事件对词面不可分 |
| 动态窗口 top-30 | 标定 NO-GO | S 档 MS 衰减不是窗口问题 |

## 6. 已知边界（主动交代）

1. Oracle 架空了会话级检索；S 档 MS/TR 衰减已定位为词面检索局限，混合检索是路线图第一位。
2. judge 代跑的 64% 误判率使分数低估语义水平；正式口径以官方复跑为准。
3. 长枚举（>12 项）抽取覆盖不全，序数查找仅覆盖点查询。
4. 遗忘模块已实现并测试，但策略参数未经 S 档调优（Oracle 无记忆损失实验）。
5. 消融矩阵为单轮，个别 Δ 在方差内（已注明），结论以多轮历史交叉印证。
