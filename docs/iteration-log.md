#### 2026-09-29 · v3.0 诊断：MS 27 道错题归因（全量 fusfull2）

| 类别 | 数量 | 实例 |

| judge 噪声/存疑 | 3 | `gpt4_7fce9456` 答案数值与 gold 一致（4=four）仍判错 |
| BM25 召回缺失 | 1 | `gpt4_ab202e7f` matched=0，靠地板兜底仍差 1 |

**根因**：v2.5 把 strict/borderline 双层改成"TOTAL MATCHED(召回大数) + 读者排除"是**减法心智**——
"3 盆植物"匹配 46 条（min_score=0.5 太松 + 类别辅路兜底），读者从 46 的噪声里手动数，误差 ±1。
v2.4 的双层方向本身正确，错在 borderline 被埋没。

**决策（v3.1）**：恢复双层，改为**加法心智**——
- STRICT（≥ max(0.45×best, 1.5)）：程序算死 `STRICT COUNT`，作为答案锚点
- BORDERLINE（中分，≤12 条显式列出）：指令"从 STRICT COUNT 出发，逐一检查 borderline，属于的加上"
- LOW（其余）：不渲染，只报数量
- agg_sum 附每事件金额提示（`_first_number`），并给 STRICT 子集的 tentative sum

#### 2026-09-29 · v3.1 全量验证：回归，回滚 ❌

**全量 500：85.40%（427/500），比 v2.6 的 86.80% 掉 7 题。**

| 题型 | v2.6 | v3.1 | Δ |
|---|---|---|---|
| multi-session | 79.70% (106) | 75.19% (100) | **-6** |
| temporal-reasoning | 85.71% (114) | 83.46% (111) | **-3** |
| KU | 88.46% (69) | 91.03% (71) | +2 |
| SS-U | 94.29% (66) | 97.14% (68) | +2 |
| SS-A | 94.64% (53) | 92.86% (52) | -1 |
| SS-P | 86.67% (26) | 83.33% (25) | -1 |

**根因（回滚后复盘）**：
1. **锚定效应**：STRICT COUNT 漏掉真事件时（BM25 词面差异），读者被程序给出的数字锚死——
   art-events 题 strict=3，读者直接答 3（gold 4，volunteering 在 borderline 里没被加上）；
2. **LOW 层隐藏**：v2.6 平铺 top-15 里低分真事件可见，v3.1 把它们藏了——
   TR/MS 里相关但词面弱匹配的事件（"volunteered" vs "attended"）从此不可见。

**教训**：①20 题冒烟 80% 是假信号——n=20 的 CI（±18pp）盖不住 ±1.4pp 的真实回归，
冒烟只能验证"管线没坏"，不能验证"渲染策略更优"；②给读者的确定性数字必须
**要么完全正确，要么明确标注不可信**——半权威的锚点比没有锚点更糟；
③v2.6 的召回大数 + "这是 RECALL 不是答案"的诚实标注，反而给了读者正确的先验。

**决策：回滚到 v2.6 渲染**（代码已还原，含注释记录失败机理）。
fusfull2 的 86.80% 仍是当前代码状态的权威实测——回滚后渲染与 v2.6 逐字节等价，
不再重跑。v3.1 的全量数据保留在 `results/fusfull3-*` 作反例存档。

**下一方向修正**：MS ±1 计数误差的正解不在渲染层（两种渲染都试过了），
而在**写入期**——把"同一现实世界事件的多会话提及"（计划→发生→后续）在关系分类中
更可靠地合并，从源头减少重复事件。这属于 KU 演化强制化方向的延伸。

| # | 根因 | 实证 |

| 1 | **同批候选从不互相比对**：关系分类只做"候选 vs 已有记忆"，同一会话多轮复述的同一事件以 paraphrase 形式全部落库 | sourdough 面包同一事件 5 个变体（"tried out a new bread recipe" / "On Tuesday, I used my sourdough starter" / "tried a sourdough bread recipe"…全部 valid_from=05-16，同一会话） |

"over-merging destroys countable events"警告，批内版保留并加强。

#### 2026-10-03 · v3.2 实现 → 全量回归 → 回滚 ❌

**A（批内 dedup）**：RELATION_PROMPT 新增 `dedup` action（同批候选互相折叠）+ `_classify` 解析 `cN` 目标与链式重定向 + `_apply` 落库跳过。
**B（subject 过滤）**：agg 意图 `_event_candidates(user_only=True)`，事件行加 `(assistant)` 标签。
**C（kind 指引）**：agg_count 指令明确"只数 user 的完成动作，排除计划/状态/assistant 建议"。

| 实验 | 结果 | 分析 |
|---|---|---|
| v3.2（A+B+C）冒烟 | 70% (14/20) | `2ce6a0f2` 被弄坏：**2 月的 art 事件在写入期被过度折叠**（Women in Art 展览、volunteering 全消失）；`gpt4_93159ced_abs` 槽位漂移（Wunderlist 无关槽位顶上）→ **A 的证据链充分：dedup 过度合并**。B/C 的渲染指令本身工作正常 |
| v3.2.1（回滚 A，留 B+C）冒烟 | 55% (11/20) | 表面暴跌，但逐题检查：5 道"新坏"里 ≥2 道**judge 噪声**（`gpt4_21adecb5` 答案正确被判错、`gpt4_93159ced_abs` 语义正确被判错）。冒烟噪声 > B/C 预期收益，必须全量裁决 |
| **v3.2.1 全量 500** | **84.60% (423/500)，-2.2pp** | 27 损 16 修，净 -11。受损集中在 TR ×10、MS ×12、_abs ×4 |

**根因（本节最重要的一条发现）**：v3.2.1 的关系分类是**全新采样**（PROMPT_VERSION 换代 → rel 缓存 key 全换 → 全部 LLM 关系调用重跑）。逐题对比显示 43 题换血（27+16），其中相当部分是**关系分类方差**——同一 prompt 下 evolve/new/merge 的判定摇摆会级联改变整个事件池和槽位聚类。
**也就是说：v2.6 的 86.80% 与 v3.2.1 的 84.60% 之间有相当部分是"关系分类这一高方差操作的采样方差"，而非 B/C 改动的真实效应。**

**结论与教训**：
1. **回滚全部三个改动**（代码已与 v2.6 逐字节等价，`results/fusfull321-*` 留作存档）；
2. **关系分类是系统最大的方差源**：任何触碰关系调用的迭代，全量分数波动 ±1.5–2pp 属于采样噪声——**没有固定 seed 的 LLM 流程，"改进"必须显著大于方差才可信**（B/C 的理论收益 ~+1pp < 方差）；
3. 写入期事件合并（A）在 LLM 单次调用判断 paraphrase 的形态下**不可行**——过合并（art 事件消失）与漏合并（sourdough 5 变体）并存，且错误不可逆地破坏了下游全部层（事件池→槽位→BM25→算术注记）。若要重做，方向应该是**确定性规则**（同日期+词面 Jaccard 阈值）而非 LLM 判断；
4. 冒烟阶段 judge 噪声率约 10%（2/20），20 题分数 ±10pp 不可信——今后冒烟只做"管线健康检查 + 明确回归定位"，**策略优劣一律全量裁决**。

**当前权威口径：v2.6 = 86.80%（434/500）。**

**下一方向（吸取本轮教训）**：写死边界，只做低方差改动——
- 官方 judge 复跑（消除 judge 噪声后重新归因，_abs 的真实水平才能看清）；
- 消融矩阵（关算术注记/关 BM25 回退跑全量——注意关系缓存全部复用 v2.6 的，只动读取侧，零方差源）；
- MS ±1 的正解改为**确定性批内去重**（同日期 + 词面 Jaccard ≥ 0.6 折叠，代码规则不进 LLM）。

2. **C 的 rel 缓存级联击穿**：evolve 改变 _active_events → 后续会话 rel 键全变 → 关系重采样。且缺 kind 守卫（Jaccard 0.45 会把"两场不同比赛"合并——v3.2 过合并同构）→ C 降级为**条件 GO**（kind=state 硬守卫 + 全量翻转审计过门槛），本轮暂缓；
3. **验证计划无统计功效**：三改动目标题合计增益上限 ~1.4pp，永远过不了 3pp 阈 → 改为**配对逐题翻转分析**（共享缓存、≥3 reader 运行、目标题须全翻对、原对题多数翻错即回滚）。
4. **更简修法**：SS-A 枚举、抽取幻觉、截断三类错共享一个底层事实——确定性层的数值缺 verbatim 原文佐证。**"数值事实必附源句"一个机制治三类**，比三个新机制便宜。

**修订后执行序**：B 收敛版（读取期枚举索引+相对序数+多列表消歧+数值事件附源句）→ A 改道版（正则窗口锚）→ C 暂缓（过审计门槛再做）。
