 LongMemEval 记忆系统（fusion）架构说明
 版本：v3.8 生产基线 / v3.9.1 S 档扩展        2026-10-12
================================================================

一、一句话总览
----------------------------------------------------------------
把非结构化对话历史编译成「自由文本事实 + 确定性时间结构」的双层
记忆；LLM 只在四个边界出现（抽取 / 关系分类 / 解析 / 作答），
中间的时间几何、聚合、守卫、渲染全部是可审计的确定性算子。

二、记忆数据模型（memory_sys/schema.py）
----------------------------------------------------------------
* Event        事实条目：subject / predicate / value / fact（自由
               文本原句，数字专名逐字保留）+ 双时间轴时间戳
               （valid_from/valid_to = 事实何时为真；stated_at =
               何时被陈述；tx_seq = 事务序号）
* Slot         同一 (subject, predicate) 的事件组成的版本链，
               支持 current()（现值）与 value_at(t)（历史时刻值）
* MemoryStore  事件全集 + 证据层（原始对话轮次，逐字保留）

三、写入期（每会话五步，memory_sys/fusion.py: write()）
----------------------------------------------------------------
1. 聚焦抽取    user 轮次逐轮抽取事实句；assistant 轮次走专名
               专项抽取（教学型事实必抽，选项列表不抽）
2. 时间解析    相对时间规则解析优先（last month / two weeks ago），
               模型解析回退，±400 天合法性校验拦幻觉日期
3. 相似检索    新事实与库内已有事实做 BM25 top-3 相似匹配
4. 关系分类    LLM 判定 new / merge / evolve / correct /
               supplement + 时间锚点（"I now have 38" 判 evolve）
5. 确定性执行  按分类执行时间几何：
               - evolve：只封旧值的有效轴（τ_v），历史可查
               - correct：连陈述轴（τ_t）一起封（旧值从未为真）
               - supplement：独立入链，不做版本闭合
               槽位归属由语义聚类在写入期继承，不依赖词面相等

四、查询期（每问题，read()）
----------------------------------------------------------------
1. 解析        LLM 把问题转成结构化查询计划
               （intent / topic / window / entities）
2. 确定性执行  按 intent 走算子：
               - agg_count / agg_sum   聚合计数与求和
               - fact_current          版本链现值
               - fact_at_time          时刻查询
               - list_events           事件列表（附时间线渲染）
               - lookup / unknown      模糊检索
               附带：算术注记（声明总量+增量 → 答出原文没有的数）、
               argmax（按数值降序）、序数查找（"第 27 项"直取原文）
3. BM25 召回   事实句 / 槽位代表句 / 句子级摘录（轮次内二次定位）
4. 近逐字证据层 v3.6：lookup/unknown 意图下把最强命中的源轮次
               全文引用（1500 字符上限）——治摘录的信息损失
5. 确定性守卫  MEMORY SCOPE NOTE   拒答措辞协议（信息不足 → 标准句式）
               PREMISE CHECK      问题专名在 user 发言零出现 →
                                  假前提拦截 + 最近邻提示
                                  （建议类问句豁免，改发
                                  RECOMMENDATION HINT）
6. 组装渲染    CURRENT-STATE LEDGER（版本链槽位的当前值+生效日期）
               + 事实清单 + PREFERENCES & OPINIONS（偏好单独成段前置）
               + ONE-HOP RELATED（实体倒排一跳扩展）
               + user 轮次全文地板（保底召回）
7. 作答        官方答题模板 + 检索上下文 → LLM 生成

五、S 档扩展（v3.9.1，仅大规模记忆生效）
----------------------------------------------------------------
* 触发门控：store > 100 events（Oracle 每题约 33 个，零行为变化）
* 实体倒排：确定性抽实体（分词去通用词）建倒排索引，惰性构建
* 一跳扩展：种子事件 top-5 的稀有实体（库内 df<=8）共现事件补进
  候选，独立段落渲染、不计入主候选计数（防锚定），由 reader 自行取舍
* 路由白名单：agg_count / agg_sum / fact_current（实测 list_events
  路由纯亏——extras 会污染时间线排序，已移除）
* 效果：S 档 48 题样本 72.92% -> 89.58%，配对 8 修 0 坏

六、遗忘与生命周期（memory_sys/lifecycle.py，默认关闭）
----------------------------------------------------------------
三条确定性策略：时效 TTL / 容量上限（按重要性分低→高归档）/
历史压缩（老版本归档）。遗忘 = 软归档：退出当前召回，但
value_at(t) 不过滤状态，历史时刻仍可审计。幂等，报告含逐条原因。
与核心检索零耦合，经 FusionMemory.forget() 三行委托接入。

七、LLM 边界（全系统仅此四处）
----------------------------------------------------------------
  1. 事实抽取（写入期，逐轮）
  2. 关系分类（写入期，逐候选）
  3. 查询解析（查询期，每题一次）
  4. 最终作答（查询期，每题一次）
时间几何 / 聚合 / 拒答判定 / 前提校验 / 渲染 / 遗忘全部是确定性
代码——每一步可单测、可回放、可审计。

八、设计原则（三条，全部有实验数据背书）
----------------------------------------------------------------
1. 数字要么完全正确、要么明确标注不可信——半权威锚点比诚实的
   召回计数更糟（v3.1 回滚教训）
2. 检索可以退化，不能丢失——BM25 模糊匹配 + user 轮次全文地板，
   措辞变体不会致命（v1 精确键匹配的教训）
3. 确定性规则的适用域必须匹配问题形态——事实性疑问才做前提
   校验，建议/推荐类问句豁免（v3.4.4 误杀 SS-P 的教训）

九、成绩摘要（glm-5.2 全链路，多运行口径）
----------------------------------------------------------------
* Oracle 500 题：86.80 ± 0.72（3 run），与全上下文上界
  87.90 ± 0.84 统计打平；SS-P 90.00 首次反超基线（87.50）；
  TR/MS 结构性领先；_abs 拒答 80%（v2.6 时代 60%）
* S 档（122k tok/题，n=48）：89.58%，四题型满分（KU/SS-A/SS-P/
  SS-U），超第三方可复现协议系（TiMem 76.9 / MemOS 77.8）
* 消融矩阵：关摘录 SS-A -7.1、关算术注记 MS -2.0、关 PREMISE
  CHECK _abs 57%——每个机制都有可归因的数字
* 交付物：results/fusfull38-hyp.jsonl（Oracle）
          results/spilot50v391-hyp.jsonl（S 档）
